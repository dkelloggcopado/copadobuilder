# DevOps Exchange Submission Checklist

Use this checklist when submitting Copado Builder (or any extension) to Copado DevOps Exchange.

## Repository and Ownership

- [ ] Source-format Git repository is available
- [ ] Repository is public (if desired for community contributions)
- [ ] Copado Labs has edit/collaboration access
- [ ] No restricted secrets/keys are committed

## Packaging and Project Setup

- [ ] Copado organization is configured as source of truth
- [ ] Project, Pipeline, Git repository, and Package records configured
- [ ] CMC SFDX app selected in package/project setup
- [ ] Namespace strategy or naming prefix strategy documented

## Documentation Readiness

- [ ] Setup guide completed
- [ ] Upgrade guide completed
- [ ] Usage guide completed (admin + developer personas)
- [ ] Manual steps documented (functions/templates/settings/credentials)

## Quality and Validation

- [ ] Fresh install tested and documented
- [ ] Upgrade path tested and documented
- [ ] Core workflow tested: Build → Deploy → Commit → Validate
- [ ] Known limitations and support model documented

## Exchange Listing Content

- [ ] Solution title
- [ ] Short description
- [ ] Long description
- [ ] Key capabilities/value
- [ ] Prerequisites
- [ ] Screenshots/assets
- [ ] Support/discussion links

## Submission Flow

- [ ] Open Copado Community footer link: **Submit Your Solution**
- [ ] Click **Submit as Individual**
- [ ] Complete all form fields
- [ ] Attach required artifacts/information
- [ ] Submit and track publication follow-up
